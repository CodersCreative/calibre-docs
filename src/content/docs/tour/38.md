---
title: Type Declarations
description: Defining named types with `type`.
---

Calibre uses `type` declarations to introduce new named types.

```cal
type Pair := struct { left right : int };
```

This binds the name `Pair` to a struct type. The same `type` form is also used for enums, tuple-style structs, and generic types.

```cal
type Language := enum {
  ENGLISH : int,
  SPANISH,
  ARABIC : <Language, Language>
};

type Country := struct (Language);
type Box:<T> := struct { value : T };
```

Calibre also allows built-in types to be named in `type` declarations when overloading or extending them.

```cal
type int := int @overload {
  "+" := fn (left right : int) => return left - right
};
```

Most of the time, though, `type` is simply how you define your own data shapes.

Once a type has been declared, it can be constructed, destructured, matched against, and extended just like the built-in types used throughout the rest of the tour.

Calibre also allows for builtin handling of type defaults using the `Default` trait and the built-in default syntax. These defaults are usually accessed using `Type.default()`

```cal
type ZimbabweanCities := enum {
    @default Harare,
    Bulawayo,
    Gweru,
    Masvingo,
    Mutare,
    Kadoma
}

type Country := enum {
    England : str,
    @default
    Zimbabwe : ZimbabweanCities = ZimbabweanCities.Bulawayo, 
}
```

By using the `@default` tag inside of an enum, you can easily define which enum variant is used by default when people call `Type.default()` and the values which are used with it. 

For example look at `Country` which is a tagged union enum and carries its own data. An `=` sign is used to show the default value to be used for that data. If the sign wasnt present `ZimbabweanCities.Harare` would've been used because it is the default value of `ZimbabweanCities`.

Next we have structs which use the `@default` tag in a similar manner to define the default value of a type.

```cal
const SURNAME := "Doe";

@default
type Person := struct {
    name: str = "John",
    surname: str = SURNAME,    
    age: int,
    country : Country = Country.England : "London",
}
```

By using the `@default` tag here, we're telling the compiler that it should generate an automatic definition for the `Default` trait where by default if we didn't assign a custom default value using `=` it will just use the type default, for example `age` here will be `0`.

You can also define a custom default function using `impl Default for Type` and by leaving out the `@default` tag.

```cal
const SURNAME := "Doe";

type Person := struct {
    name: str,
    surname: str,    
    age: int,
    country : Country,
}

impl Default for Person {
  const default := fn -> Self => {
    return Person {
      name : "John",
      surname : SURNAME,
      age : 0,
      country : Country.England : "London",
    };
  };
}
```

This example produces the exact same functionality as the one using the `@default` tag but helps give us more control especially if multiple attributes depended on the same value.

Finally here is an example of us getting the default and printing it manually:

```cal
const main := fn => {
    let person := Person.default();
    print("Person: " & person);
}
```
